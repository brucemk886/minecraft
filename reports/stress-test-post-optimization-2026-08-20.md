# 跑酷批量生成优化后压测（2026-08-20）

## 结论

- 100、300、1000、4500 条模拟任务均能完成，没有最终失败任务。
- 300 个模板在两天内完整覆盖：每天 150 个，连续两天交集为 0，合计覆盖 300 个。
- 主题区域纵向间距由 2560 扩大到 5120。2、2.5、3、5、10、15 分钟单向路线均不会进入相邻主题区域；15 分钟仍保留约 752 格余量。
- 默认单条时长调整为 2 分钟，10/15 分钟仍可手动选择。
- 每完成 50 条自动停止跑酷、释放录制源、等待并重新检查游戏和磁盘，再继续下一条。
- 输出盘可用空间低于 20GB 时不会开始新视频，会保留断点并暂停批次，避免写满磁盘。
- 现有世界升级到 `grid60-v3` 时保留原锚点，只清理旧版高度缓存，不删除用户世界里的方块。

## 稳定性模拟

| 模拟规模 | 最终失败 | 说明 |
|---:|---:|---|
| 100 | 0 | 前 100 个模板不重复 |
| 300 | 0 | 完整覆盖 300 个模板 |
| 1000 | 0 | 出现视觉相似候选时自动换种子重试 |
| 4500 | 0 | 候选冲突均在有限重试内解决 |

## 自动化验证

- Node 自动化测试：30/30 通过。
- Fabric 模组：Gradle 构建通过。
- 当前 D 盘检测可用空间约 188.9GB，高于 20GB 安全线。
- 正式程序打包前会同步同一份最新模组到运行时目录和 Minecraft `mods` 目录，并核对 SHA-256。

## 运行边界

官方 Minecraft Launcher 不提供本项目可依赖的稳定无人值守启动接口，因此每 50 条采用“软维护”而不是强杀游戏：释放捕获资源、停止当前跑酷、短暂等待、确认 Minecraft 仍存活后继续。若游戏已退出，程序会保留断点并打开 Launcher，避免无画面录制。
